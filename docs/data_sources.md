# 데이터 출처와 확보 절차

`--source live` 로 전환할 때 필요한 원본과, 각각을 어디서 어떻게 받는지 정리한다.
코드에서 직접 크롤링하지 않는 이유는 두 가지다 — 통계표 배포 형식이 자주 바뀌고,
소스마다 이용약관이 다르다. 정규화 책임만 `src/snx/ingest/live_sources.py` 가 진다.

---

## 1. 자동차 등록 현황 (필수)

**받을 곳**

- 국토교통 통계누리 — 「자동차 등록현황보고」 <https://stat.molit.go.kr>
- KOSIS 국가통계포털 — 자동차등록대수 현황 <https://kosis.kr>
- 공공데이터포털 — 국토교통부_자동차 등록 현황 <https://www.data.go.kr>

**필요한 절단면**: 시군구 × 차령 × 연료

통계누리의 월간 등록현황은 시군구 × 차종(승용/승합/화물)까지는 공개되지만
차령 절단면은 연간 보고서나 별도 요청이 필요할 수 있다. 차령 분포를 지역 단위로
확보하지 못하는 경우의 대안:

1. 전국 차령 분포를 시도 단위 신규등록 이력으로 안분
2. 자동차 검사 이력(한국교통안전공단 TS) 의 지역별 차령 통계로 대체
3. 차량 말소등록 통계로 지역별 평균 차령을 역산

**저장 위치**: `data/raw/vehicle_registration.csv`

```csv
sigungu_code,age_bucket,vehicles,ev_vehicles
41360,0-2,18420,1650
41360,3-5,21030,890
...
```

`vehicles` 는 전 브랜드 합계로 넣는다 — 로더가 `market.hyundai_share` 를 적용해
자사 모수로 환산한다. 지역별 브랜드 점유율 데이터가 있다면
`live_sources._load_parc` 의 단일 계수 적용부를 지역별 조인으로 바꾼다.

## 2. 서비스 거점 목록 (필수)

**받을 곳**

- 브랜드 공식 서비스망 안내 페이지 (지점명 · 주소 · 연락처)
- 사내 네트워크 마스터 (워크베이 수 · 정비 등급)

주소만 있고 좌표가 없으면 지오코딩이 필요하다.

- 카카오 로컬 API (일 30만 건 무료) <https://developers.kakao.com>
- 네이버 지도 API <https://www.ncloud.com>
- 도로명주소 API (행정안전부) <https://business.juso.go.kr>

**워크베이 수를 모르는 경우**: 로더가 기본값 5 를 넣는다. 정비 등급(일반/종합)만
알아도 등급별 대표값으로 치환하는 편이 낫다 — 용량 갭 계산의 정확도가 여기에 달렸다.

**저장 위치**: `data/raw/service_centers.csv`

```csv
center_id,name,center_type,sigungu_code,lat,lon,bays
41360-B01,○○지점,bluehands,41360,37.6412,127.2203,6
```

## 3. 거점 VOC · 재입고율 (선택)

**받을 곳**

- 고객 VOC 관리 시스템 — 거점별 불만 접수 건수 (콜센터 · 앱 · 홈페이지 채널 합산)
- 정비 이력(DMS) — 30일 내 동일 증상 재입고 건수, 반기 입고 실적

**가공**: 반기 단위로 `VOC 건수 ÷ 입고 건수 × 1,000` 과 `재입고 건수 ÷ 입고 건수` 로 비율화한다.
건수 그대로 넣으면 큰 거점이 불리해진다. 재입고율을 % 로 넣어도 로더가 비율로 환산한다.

없으면 품질 진단은 부하율(추정 대기일수) 축만으로 계산하고, 원인 유형은 '대기 리스크'까지만 판정한다.

**저장 위치**: `data/raw/center_voc.csv`

```csv
center_id,period,voc_per_1k_jobs,comeback_rate
41360-B01,2026H1,2.4,0.031
```

## 4. 시군구 참조표 (저장소 동봉)

`data/reference/sigungu.csv` — 시군구 코드 · 중심좌표 · 도시등급 · 인구.

현재 값은 **근사 중심좌표**다. 정밀도를 올리려면:

- 행정구역 경계 SHP — 통계지리정보서비스 SGIS <https://sgis.kostat.go.kr>
  → 인구가중 중심점(population-weighted centroid)을 계산해 대체하면
    면적이 넓은 군 지역의 접근성 추정이 크게 개선된다
- 주민등록인구 — KOSIS <https://kosis.kr> (매월 갱신)

`urban_class` 는 metro(특별·광역시 및 인구 50만 이상 시) / city(일반 시) /
rural(군 및 인구 20만 미만) 기준으로 부여했다. 평균 주행속도 배정에만 쓰인다.

## 5. 선택 — 정확도 개선용

| 데이터 | 용도 | 출처 |
|---|---|---|
| 라우팅 소요시간 | 직선거리 근사 대체 | OSRM 자체 구축 / T-Map API / 카카오내비 API |
| 자동차 검사 이력 | 차령별 실제 입고 빈도 캘리브레이션 | 한국교통안전공단 |
| 리콜·결함신고 | 지역별 정비 수요 스파이크 | 공공데이터포털 자동차리콜센터 |
| 전기차 충전소 | 하이테크센터 입지 보조 지표 | 한국환경공단 |
| 지역별 소득·차량 구매력 | 신차 비중 추정 개선 | KOSIS 지역소득 |
| 보증수리 청구 실적 | 차령별 보증 비중(`warranty_share`) 캘리브레이션 | 사내 보증 청구 시스템 |
| 거점 증설 · 신설 실집행 단가 | `investment` 단가 가정 교체 | 사내 네트워크 투자 이력 |

## 6. 확보 순서 권장

1. 시군구 참조표를 SGIS 인구가중 중심점으로 교체 (무료 · 즉시 · 효과 큼)
2. 등록 현황을 실제 통계로 교체 — 차령 절단면이 없으면 시도 단위 안분으로 시작
3. 거점 목록 확보 + 지오코딩
4. 워크베이 수를 정비 등급 대표값으로 보강
5. VOC · 재입고율 반기 집계 연결 — 품질 진단의 원인 분리가 여기서부터 의미를 갖는다
6. 라우팅 API 연동

1~3 만 해도 sample 모드와 비교해 순위가 어떻게 바뀌는지 볼 수 있고,
그 자체가 "가정이 결과를 얼마나 흔드는가"에 대한 민감도 분석이 된다.
